## Contract changes
- **flow:** FLOW-2 becomes "no stage starts before the previous artifact is approved": `Approved-by:` on brief, research, outline, draft; `Signed-off-by:` on final (FLOW-6 unchanged). Five human checkpoints, not two.
- **data:** `articles/<slug>/approvals/<stage>.r<rev>.json` `{doc_id, rev, artifact_sha256, value, at}` and `articles/<slug>/.docs-created.json` (id and title of each Doc the copy skill created), both written only by hooks; hash = `text_hash` (approval lines ignored). A comments file is *pending* when it has the highest `k`, its `Artifact sha256` equals the current hash and it has a `· OPEN` thread. New backup `research.prev.<n>.md`.
- **boundary (additive):** `article-status.py` JSON gains `comments`; `next: approve` names the stage. **Doc text:** one visible instruction, only while the line is empty; the next copy of each article is a new Doc once (ADR-012.3).
- **hooks.json (ask-first path):** PostToolUse on the Drive `read_file_content` and `create_file`; PreToolUse also matches the whole `mcp__claude_ai_Google_Docs__.*` and `mcp__claude_ai_Google_Drive__.*` prefixes; the read tools R0 finds are an allow-list, everything else on a logged Doc id is refused. **skills:** sync gains Edit (PR 1); in PR 2 sync gains `Skill` and research, outline, draft and edit gain `Bash(...article-status.py *)`.
- Existing articles: a missing approval line is "not approved" (A5); a human adds the line to resume. Verdict hashes are unaffected.

### R3 — Guard (L)
- files: `bin/guard-stage-order.py`, `bin/lib/writer.py` (`approved`), `tests/test_hooks.py`
- **fail closed** (ADR-012.5, a false allow breaches FLOW-2/FLOW-6): the approval-write rule, the `create_file` rules, the refusal of any tool not on the read allow-list for a logged Doc id, and the `docs.json` entry match refuse when the log, the record or the tool input cannot be read, including, for a write tool, a Doc id that cannot be found in the input. Scope: a missing log is an empty log (every existing article, every non-workspace project); only a log that exists but cannot be parsed fails closed; allow-listed calls with no Doc id (`search_files`, folder `create_file`) pass. These rules run in their own wrapper that blocks (FLOW-2 or FLOW-6) on any exception, outside the guard's outer `fail_open`, and refuse a non-dict `tool_input` for a matched Drive or Docs tool; the choice is recorded in ADR-016. Tests force an unexpected exception inside each rule and assert exit 2. One test per rule with a corrupt log or record; `search_files` and a folder create pass with no log; a Drive call in a directory with no `articles/` passes; a corrupt log refuses a write tool on an id. The R2 recorder stays fail-open: a failure there records nothing.
- stage order: writing `<stage>.md` needs the previous artifact approved (brief→research→outline→draft→final).
- approval writes: a Write or Edit that makes an approval line non-empty is allowed only if `approvals/<stage>` holds that value for the current hash (`Signed-off-by:` keeps its G4 rule too); a clearing write is allowed; no tool writes `approvals/` or `.docs-created.json`.

## Risks
| Risk | Impact | Cheapest way to find out early |
|------|--------|--------------------------------|
| The hook does not get the Doc text, or the read-back never equals the upload | R2 to R5 change design | R0 first, before any code |
| The model forges a Doc approval (filled upload, a copy, an `update_doc` edit, a hand-made `docs.json` entry) | A human checkpoint skipped | R2 and R3 tests for each; a write tool R0 shows cannot be refused goes to a human (F2), not into an accepted gap |
| A Bash write fills an approval line | The same | Known gap (final's sign-off has it today, ADR-010); not claimed closed |
| Whoever can edit a Doc can approve | A weaker checkpoint if a Doc is shared widely | ADR-016 says so; the name is recorded; Drive sharing is the control |
| A stage obeys an instruction in a comment | A write outside the artifact | R6's run; R3 refuses any non-empty approval without a record |
| Human answers never clear a marker, so a final built on them cannot be signed off | The flow ends at FLOW-6 for those claims | Stated in the research stage's report and ADR-016; a human-fact row type is a later change |
| `/sync` restarts a stage that then BLOCKs | A FLOW-3 strike from a comment | The stage lists what it skipped; two BLOCKs hand over to a human as before |
| Existing articles stop at `approve` | A surprise on upgrade | CHANGELOG and status text say what to add |
